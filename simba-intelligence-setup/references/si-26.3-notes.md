# Simba Agentic Intelligence 26.3: what changes for setup

<!-- Written 29 September 2026. 26.3 had not been released when this was written. -->

**Read this before following any install, upgrade, ingress or teardown guide in
this skill.** Every guide here describes 26.2 and earlier, and 26.2 remains
correct for 26.2. From 26.3 the deployment shape changes in ways that make
several of those procedures fail rather than degrade.

**Status.** Everything on this page pertains to an unreleased version and is
subject to change. Nobody who wrote this skill has installed 26.3, and no
procedure below has been executed. This page is a warning about what moves, not
a replacement procedure. Where a step is unknown it is written as unknown.

Sources are Jira keys in PY (Simba Agentic Intelligence, "SI" below) and SCP and
CMP (Logi Composer), Confluence page ids in the SCP space, and the public
Composer documentation site.

---

## 1. The standalone SI Helm chart goes away

From 26.3, SI ships as a sub-component of the Logi Composer chart (PY-693). The
standalone `simba-intelligence-chart` is deprecated (PY-701). Confluence page
18711380170 records the arrangement several guides here assume, a separate SI
chart pointing at a Composer hosted elsewhere, as no longer supported in 26.3
and later.

Three consequences:

- Every `helm install`, `helm pull` and `helm upgrade` in this skill that names
  `oci://docker.io/insightsoftware/simba-intelligence-chart` describes the 26.2
  path. Those commands are annotated in place; they stay as written because they
  still work for 26.2.
- A customer running SI with no BI at all still deploys the Composer chart. That
  is a packaging requirement, not a convenience.
- The air-gapped procedure mirrors one chart today. From 26.3 the artefact to
  mirror is the Composer chart, and its image list is not the SI chart's image
  list. Nobody has enumerated it.

One public, non-Atlassian signal agrees with PY-701. On 29 September 2026 the
Docker Hub repository `insightsoftware/simba-intelligence` already carries a
`26.3.0` application image tag, while `insightsoftware/simba-intelligence-chart`
stops at `26.2.1` with no 26.3 tag at all:

```bash
curl -s 'https://hub.docker.com/v2/repositories/insightsoftware/simba-intelligence-chart/tags?page_size=100'
curl -s 'https://hub.docker.com/v2/repositories/insightsoftware/simba-intelligence/tags?page_size=100'
```

The application ships at 26.3 and the standalone chart does not. That is
consistent with the chart being retired rather than proof of it, since a tag
absent the day before release may simply be a tag not yet pushed. Re-run the two
commands before relying on either reading.

**There is no upgrade path to follow yet.** The transition guide is ticket
PY-706, which was unfinished when this was written. Do not improvise one. If you
need to move an existing 26.2 deployment to 26.3, treat it as unsolved and ask,
rather than adapting an install guide.

Composer's own Kubernetes support is public and states that Kubernetes is
supported for new installations only from version 26.3 and later, via the Helm
chart `composer/composer`:
<https://insightsoftware.mintlify.app/simba-embedded-analytics/docs/self-service-analytics/26.3/>

That is a second reason not to guess. Composer on Kubernetes is itself new, and
the public documentation scopes it to new installations.

## 2. SI moves off the root path

SI served at `/` becomes `{composer-context}/intelligence`, default
`/composer/intelligence` (Confluence page 18711380170). This breaks bookmarks,
saved API clients, ingress rules, reverse-proxy configuration and any script
that assumes SI answers at the root of its host.

The context path stays configurable, so the `/discovery` prefix used throughout
this skill survives where an admin sets it, and stops being what a default
install gives you. Read the context path from configuration rather than treating
any literal in these guides as a constant.

**MCP is the exception that makes this awkward.** The same page records that the
MCP server must be served at root (`/`) or disabled entirely, describes it as a
protocol limitation, and states explicitly that it is not fixed for 26.3. The
routing rule in `../SKILL.md` therefore needs reading against that page before
you plan a 26.3 ingress, because the two constraints pull in opposite
directions. How they are meant to coexist is not documented anywhere this skill
could find.

## 3. SI stops having its own sign-in

The SI UI and its related frontend APIs are being removed in 26.3. Users sign in
through Composer. PY-689 gives the reason plainly: SI's own login does not work
with SAML and Composer's does, so SI inherits Composer's SAML by abolishing its
own login rather than by implementing SAML itself.

Single sign-on with Composer is not new. It shipped in 26.2 under PY-530. What
26.3 adds is the removal of the alternative.

Operational effect on this skill: every instruction to log in to SI directly,
including the default-credential step in `deployment-eks.md` and the
supervisor-account step in `llm-config.md`, describes a sign-in that 26.3
removes. Those steps are annotated in place.

SAML was exercised against a 26.3.0 build under SCP-454 and CMP-8739. One
Composer defect is still open at the time of writing: SCP-1124 records the
Custom User Attribute fields on Composer's SAML admin page as not editable,
which leaves attribute mapping unusable from that UI. Check it before planning a
26.3 deployment around SAML attribute mapping.

## 4. LLM configuration and rules move to a Composer admin area

LLM Configuration and Agentic Rules move under Composer's Administration >
Tools (Confluence page 18773016632, epic SCP-314). The direct paths this skill
navigates to, `/llm-configuration` in `llm-config.md` and
`gui-install-guide.md`, describe SI's own admin UI, which goes with the rest of
the SI frontend.

The `POST /api/v1/rules` surface documented in
`best-practices-data-sources.md` and `platform-only-modelling.md` is a REST
endpoint rather than a UI path. Nothing found says it changes, and nothing found
says it survives. Treat it as unverified on 26.3 until somebody probes a live
instance.

## 5. What this page deliberately does not tell you

26.3 carries product changes beyond deployment. They are out of scope here
because this is a public repository and 26.3 is unreleased, and because none of
them would make a command in this skill fail. Ask internally rather than
inferring them from this page.

Two specific cautions for anyone tempted to fill the gap from memory:

- Claude models have been available in SI through AWS Bedrock since before 26.3
  (`llm-config.md`). Anything you read about 26.3 and Claude is about a
  different hosting route, not about Claude arriving in SI.
- Rule-aware semantic caching was already claimed as shipped in 26.2 under
  PY-498 (`si-26.2-release.md`). Whatever 26.3 says about cache and rules is
  either a completion of that or a restatement of it, and the documents
  available to this skill cannot tell the two apart.

## 6. Open questions this skill cannot answer

- The 26.3 upgrade path for an existing standalone deployment (PY-706
  unfinished).
- Whether a 26.3 standalone chart tag appears after release, or whether
  `insightsoftware/simba-intelligence-chart` stops at 26.2.1 for good.
- The image list and mirroring procedure for an air-gapped 26.3 install.
- Whether the MCP root-path requirement and the `{composer-context}/intelligence`
  move are compatible in one ingress.
- Whether `POST /api/v1/rules` and the other undocumented REST surfaces in this
  skill survive the frontend removal.
- What the EDC enablement values keys become once the SI chart is a sub-chart of
  the Composer chart, which affects `enabling-edcs.md` and
  `datasphere-connector.md`.

## 7. The repo's own gate is red because of this, and bumping the pin is wrong

`verify-skill.py` check `si_version_not_behind_release` reads the
`CHART_VERSION` defaults out of `../scripts/install-si.sh`,
`install-si-aks.sh` and `Install Simba Intelligence.command`, compares them
against the newest release tag on Docker Hub, and now fails: they pin 26.2.1 and
the application image repository is at 26.3.0.

**Do not resolve it by bumping the pins.** The pins name a chart version, the
check reads an application image repository, and the chart has no 26.3 tag. A
bump would produce an install command that cannot resolve. `README.md` says
every tagged release runs the gate first, so this needs deciding before the next
tag is cut: either the check learns to compare against the chart repository, or
it learns that the chart is deprecated. Neither is done here, because changing a
check to make it pass is how a gate stops meaning anything.
