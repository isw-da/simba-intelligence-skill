## Official summary (verbatim intent)

> This release improves reliability, deployment flexibility, and day-to-day usability.
> Key updates: single sign-on with Composer, task-based asynchronous Data Source Agent
> runs that survive page refreshes, Helm/Kubernetes deployment improvements, expanded
> model/provider options (Ollama, Bedrock), stronger handling of hidden fields, disabled
> capabilities, cache invalidation and timeouts. Remaining Symphony integration removed;
> Simba Intelligence continues as a Composer-aligned product.

## Corrections to earlier reverse-engineered notes

1. `search_data_sources` (arg `search_subject`) is the **intended** tool per PY-487, not
   a documentation error. The MCP guide simply predates the rename from `get_data_sources`.
2. The streaming `POST /agents/data-source/run/{connection_id}` is **deprecated** (PY-560);
   new integrations should use the async task endpoint.
3. **Embeddings-switch de-risk:** 26.2 automatically detects and wipes tenant-scoped vector
   indexes when the embeddings model changes (PY-557). This materially lowers the risk of
   switching an existing instance's embeddings provider (e.g. Vertex → Azure): the stale
   source-match vectors are cleaned automatically rather than silently mismatching. Still
   verify source selection after switching, but the old "you must fully rebuild sources"
   caution is softened **on 26.2**.

## Live-only detail (accurate, not in the notes)

- The app serves its own OpenAPI spec at **`/apispec_1.json`** (title "Simba Intelligence
  API", 26.2.0, 32 paths) with Swagger UI at **`/apidocs/`**. The public Mintlify
  `openapi.json` is a placeholder. **[live-only]**
- Direct data-query REST API returning structured results without the chat wrapper:
  `POST /api/v1/data/query[/{source_id}][/stream]` — verified. **[live-only]**
- Question history + feedback: `POST /history/search` (hybrid semantic+keyword),
  `PUT /history/question/{id}` (upvote/downvote), `/query-summary`; table `question_records`. **[live-only]**
- `GET /api/v1/version`, `POST /api/v1/auth/reset-trusted-access`. **[live-only]**
- Native MCP OAuth2 PKCE proven end to end (register → authorize → consent → token →
  tool call) including over a public HTTPS tunnel; per-identity governance holds (a
  no-grant user gets `read:data` only, empty source list, and a hard 403 on an explicit
  source id). Tools: `get_data`, `search_data_sources`, `get_suggested_questions`,
  `get_field_statistics`; `prompts`/`resources` empty. **[live-only]**
- Undocumented env: `FIELD_VALUE_CACHE_BUDGET_MB`, `QUESTION_RECORD_RETENTION_DAYS`,
  `DEBUG_MODE`, `POSTGRES_*`, `COMPOSER_ADMIN_*`, `REDIS_PASSWORD`. **[live-only]**
